1. Core Architecture Breakdown

The High-Level Blueprint

Angular is a platform, not merely a view library. At runtime, your application is two distinct trees operating in parallel:

<
  1. The Component Tree: The UI hierarchy rendered via the platform renderer.
  2. The Injector Tree: A hierarchical dependency resolution graph that mirrors (but is not identical to) the component tree.

Every component, directive, pipe, and service participates in both trees. Understanding the relationship between them is the single most important mental model shift.

The Mental Model Shift

Concept Java / Backend Mental Model Angular Mental Model
Architecture MVC (Spring Boot), Request/Response Component Tree + Services, Client-side routing, Long-lived SPA state
Dependency Injection Global Application Context (Singletons, Request Scopes) Hierarchical Injector Tree tied to the UI Component Tree
State & Data Flow Database transactions, Thread-local state, DTOs Reactive streams (RxJS) and Signals (Push-based reactivity)
Views & Templates Server-rendered templates (JSP, Thymeleaf) Compiled components with reactive bindings and control flow

Modern Building Blocks (Angular 17+)

Standalone Components

NgModule is legacy. Modern Angular defaults to Standalone Components. A component is self-describing: it declares its own dependencies, routing metadata, and provider scope. 

// main.ts
import { bootstrapApplication } from '@angular/platform-browser';
import { AppComponent } from './app/app.component';
import { appConfig } from './app/app.config';

bootstrapApplication(AppComponent, appConfig).catch(err => console.error(err));

// app.component.ts
import { Component } from '@angular/core';
import { RouterOutlet } from '@angular/router';
import { HeaderComponent } from './shell/header.component';

@Component({
  selector: 'app-root',
  standalone: true,
  imports: [RouterOutlet, HeaderComponent], // Self-describing dependency graph
  template: `
    <app-header />
    <router-outlet />
  `,
  changeDetection: ChangeDetectionStrategy.OnPush
})
export class AppComponent {}

Directives & Pipes

Attribute Directives modify host element behavior (e.g., permission-based visibility). Structural logic is now handled via template control flow (@if, @for, @switch) in Angular 17+, replacing *ngIf and *ngFor.

Pipes are pure transformation functions in templates. In signal-based architectures, prefer computed() over custom pipes for derived state. The async pipe is obsolete when using toSignal().

Services & The inject() Paradigm

Services are plain TypeScript classes decorated with @Injectable. The modern pattern uses the inject() function instead of constructor injection, enabling cleaner inheritance and safer use in lifecycle hooks. 

@Injectable({ providedIn: 'root' })
export class UserService {
  private readonly http = inject(HttpClient);
  private readonly config = inject(APP_CONFIG);

  readonly users = signal<User[]>([]);

  loadUsers(): void {
    this.http.get<User[]>(`${<this.config.apiUrl}/users`)
      .pipe(takeUntilDestroyed()) // Auto-unsubscribe via DestroyRef
      .subscribe(data => this.users.set(data));
  }
}

Dependency Injection (DI) Deep Dive

If you know Spring or Guice, you know DI. However, Angular's DI is a hierarchical tree of injectors tied to the UI, not just a flat application context.

  • Root Injector: Created at bootstrap. providedIn: 'root' registers here.
  • Component Injector: Each component can declare providers: [...], creating a child injector scoped to that component and its descendants.
  • Resolution Algorithm: Angular walks up the injector tree from the requesting component until it finds a provider. If none is found, it throws (unless @Optional() is used).
// Hierarchical override pattern
export const API_URL = new InjectionToken<string>('api.url');

// Parent provides default
providers: [{ provide: API_URL, useValue: 'https://api.default.com' }]

// Child feature overrides
@Component({
  providers: [{ provide: API_URL, useValue: 'https://api.billing.com' }]
})
export class BillingComponent {
  // Resolves to the overridden billing URL, not the root default
  private readonly apiUrl = inject(API_URL);
}

Change Detection: Zone.js vs. Signals

Mechanism Trigger Performance Model
Zone.js (Legacy) Monkey-patches all async APIs (setTimeout, Promise, XHR, DOM events). Any async callback triggers global CD. O(n) tree traversal. Error-prone, heavy bundle cost.
Signals (Modern) Explicit write (.set(), .update()) notifies subscribers. O(1) granular updates. No Zone.js needed. Use OnPush everywhere. 
import { signal, computed, effect } from '@angular/core';

export class Store {
  private readonly state = signal<State>(initialState);

  // Public readonly access
  readonly users = computed(() => this.state().users);
  readonly activeCount = computed(() => this.users().filter(u => u.active).length);

  constructor() {
    // Side effect: runs whenever activeCount changes
    effect(() => {
      console.log('Active users:', this.activeCount());
    });
  }

  setUsers(users: User[]): void {
    this.state.update(s => ({ ...s, users }));
  }
}

3. Essential Core Features (The 80/20 Toolkit)

3.1 Reactive Forms: Typed & Dynamic

Angular Reactive Forms provide an imperative, observable model of the form state. Angular 14+ introduces strict typing. Angular 17+ defaults favor standalone components with ReactiveFormsModule imported directly.

Strictly Typed Form Model

import { Component, inject } from '@angular/core';
import { FormBuilder, FormGroup, FormControl, FormArray, Validators, ValidatorFn, ValidationErrors, AbstractControl } from '@angular/forms';
import { takeUntilDestroyed } from '@angular/core/rxjs-interop';

interface ProjectForm {
  name: FormControl<string>;
  ownerEmail: FormControl<string>;
  budget: FormControl<number>;
  tags: FormArray<FormControl<string>>;
}

@Component({
  selector: 'app-project-form',
  standalone: true,
  imports: [ReactiveFormsModule],
  template: `...`
})
export class ProjectFormComponent {
  private readonly fb = inject(FormBuilder);

  form = this.fb.group<ProjectForm>({
    name: this.fb.control('', { nonNullable: true, validators: Validators.required }),
    ownerEmail: this.fb.control('', {
      nonNullable: true,
      validators: [Validators.required, Validators.email]
    }),
    budget: this.fb.control(0, { nonNullable: true, validators: Validators.min(0) }),
    tags: this.fb.array<FormControl<string>>([])
  });

  constructor() {
    // React to value changes with automatic cleanup
    this.form.valueChanges.pipe(takeUntilDestroyed()).subscribe(v => {
      console.log('Form dirty state:', this.form.dirty, v);
    });
  }

  addTag(value: string): void {
    this.form.controls.tags.push(this.fb.control(value, { nonNullable: true }));
  }
}

Cross-Field & Async Validators

// Generic cross-field validator
export const dateRangeValidator: ValidatorFn = (control: AbstractControl): ValidationErrors | null => {
  const start = control.get('startDate')?.value;
  const end = control.get('endDate')?.value;
  return start && end && new Date(start) > new Date(end) ? { dateRange: true } : null;
};

// Async validator factory
export function uniqueEmailValidator(userService: UserService): AsyncValidatorFn {
  return (control: AbstractControl) => {
    if (!control.value) return of(null);
    return userService.checkEmail(control.value).pipe(
      map(isTaken => (isTaken ? { uniqueEmail: true } : null)),
      catchError(() => of(null))
    );
  };
}

3.2 Routing & Navigation

Modern Angular routing is flat, lazy, and function-driven. loadComponent replaces legacy module-based lazy loading.

Lazy Loading & Route Configuration

// app.routes.ts
import { Routes } from '@angular/router';

export const routes: Routes = [
  {
    path: '',
    pathMatch: 'full',
    redirectTo: 'dashboard'
  },
  {
    path: 'dashboard',
    loadComponent: () => import('./features/dashboard/dashboard.component').then(m => m.DashboardComponent)
  },
  {
    path: 'admin',
    loadComponent: () => import('./features/admin/admin.component').then(m => m.AdminComponent),
    canActivate: [authGuard],
    canDeactivate: [unsavedChangesGuard],
    resolve: { permissions: adminPermissionsResolver },
    data: { breadcrumb: 'Administration', roles: ['admin'] },
    children: [
      {
        path: 'users',
        loadComponent: () => import('./features/admin/users.component').then(m => m.UsersComponent)
      }
    ]
  },
  { path: '**', loadComponent: () => import('./shell/not-found.component').then(m => m.NotFoundComponent) }
];

Functional Guards & Resolvers

Class-based guards are deprecated. Use functional guards with inject() for full access to DI. 

import { CanActivateFn, CanDeactivateFn, ResolveFn, Router } from '@angular/router';
import { inject } from '@angular/core';

export const authGuard: CanActivateFn = (route, state) => {
  const store = inject(AuthStore);
  const router = inject(Router);
  return store.isAuthenticated() ? true : router.parseUrl('/login');
};

export const unsavedChangesGuard: CanDeactivateFn<EditorComponent> = (component) => {
  return component.isDirty() ? confirm('Discard changes?') : true;
};

export const adminPermissionsResolver: ResolveFn<Permission[]> = () => {
  return inject(PermissionService).fetchForModule('admin');
};

Route Signals & Component Input Binding

With withComponentInputBinding(), route parameters are automatically bound to component inputs as signals. 

@Component({...})
export class UserDetailComponent {
  // Automatically populated from :id route param
  userId = input.required<string>();

  private readonly userService = inject(UserService);
  readonly user = toSignal(
    toObservable(this.userId).pipe(
      switchMap(id => this.userService.getById(id))
    ),
    { initialValue: null }
  );
}

3.3 HTTP Client & API Integration

Angular 17+ uses the functional interceptor API and provideHttpClient. RxJS remains the backbone, but signals are the preferred consumption layer in components.

Functional Interceptors

import { HttpInterceptorFn, HttpRequest, HttpHandlerFn } from '@angular/common/http';
import { inject } from '@angular/core';
import { catchError, throwError } from 'rxjs';

export const authInterceptor: HttpInterceptorFn = (req: HttpRequest<unknown>, next: HttpHandlerFn) => {
  const token = inject(AuthStore).token();
  if (!token) return next(req);

  const authReq = req.clone({
    setHeaders: { Authorization: `Bearer ${token}` }
  });
  return next(authReq);
};

export const errorInterceptor: HttpInterceptorFn = (req, next) => {
  const notifier = inject(NotificationService);
  return next(req).pipe(
    catchError(err => {
      if (err.status === 401) inject(AuthStore).logout();
      else notifier.showError(err.error?.message || 'Request failed');
      return throwError(() => err);
    })
  );
};

Bridging RxJS & Signals

import { toSignal } from '@angular/core/rxjs-interop';
import { HttpClient, HttpContext } from '@angular/common/http';
import { shareReplay, switchMap } from 'rxjs';

const SKIP_INTERCEPTOR = new HttpContext().set(new HttpContextToken<boolean>(() => false), true);

@Injectable({ providedIn: 'root' })
export class UserApiService {
  private readonly http = inject(HttpClient);

  private readonly refresh$ = new Subject<void>();

  // Signal derived from RxJS stream with shareReplay for multicast
  readonly users = toSignal(
    this.refresh$.pipe(
      startWith(null),
      switchMap(() => this.http.get<User[]>('/api/users')),
      shareReplay({ bufferSize: 1, refCount: true })
    ),
    { initialValue: [] as User[] }
  );

  invalidateCache(): void {
    this.refresh$.next();
  }
}

Context-Aware Requests

Use HttpContext to pass metadata to interceptors per-request without abusing headers. 

this.http.get('/api/public', {
  context: new HttpContext().set(SKIP_AUTH, true)
})

Exercise 5: Signal-Based API Resource with Interceptor Mesh

Build a generic, reusable data access layer for CRUD operations.

  • Create a generic ApiResource<T> class (not a service) that wraps HttpClient using signals. It must expose:
    • data: Signal<T[]>
    • loading: Signal<boolean>
    • error: Signal<HttpErrorResponse | null>
    • refresh(): void to re-trigger the fetch
  • Implement automatic refresh: the resource should re-fetch every N seconds (configurable) but only when the browser tab is visible (use document.visibilitychange).
  • Implement request deduplication: if refresh() is called while a request is in-flight, do not spawn a second request.
  • Build a cacheInterceptor using a Map<string, WritableSignal<any>>. It should cache GET responses and invalidate entries based on a TTL (passed via HttpContext). The interceptor must be stateful and shared across the app.
  • Integrate optimistic updates: expose an optimisticUpdate(updater: (current: T[]) => T[]): void method that mutates the local signal immediately, then reconciles with the server response.
